Featured case study

Inventory & Order Tracking: a business analysis

I defined requirements for a small supplier's inventory and ordering system, built a SQL database, and analyzed it to answer real operations questions: what to reorder, what earns margin, where shipping is slow.

Practice sample. The company, products and numbers are hypothetical and were created for this exercise. This is not employer data and not work experience. The analysis, SQL and documents are real and downloadable below.

The problem

A small wholesale supplier tracks stock and orders in spreadsheets. Staff find out about low stock only when an order can't be filled, some regions ship slowly, and managers can't see which products or customers drive profit.

StakeholderWhat they need
Operations managerFewer stock-outs, faster shipping
Warehouse staffA clear pick/ship queue and accurate counts
PurchasingA timely reorder list with supplier lead times
FinanceRevenue and margin by category and customer

Current process (as-is)

Order by email→Check spreadsheet→Manual pick list→Ship→Late status update→Weekly stock fix

Proposed process (to-be)

Order entered once→Stock check + shortfall flag→Generated pick list→Status with timestamps→Stock updates on pick→Daily reorder list

Functional requirements

  • FR1 Record orders with customer, date, status and line items.
  • FR2 Reduce on-hand quantity when an order is picked; never allow negative stock.
  • FR3 List products at or below reorder point with supplier and lead time.
  • FR4 Report revenue and margin by category and customer, excluding cancelled orders.
  • FR5 Report average days from order to shipment by region.

Non-functional

  • NFR1 Reports refresh daily and run in under 5 seconds for 10,000 orders.
  • NFR2 Only authorized staff can change stock counts; changes are logged.

User stories & acceptance criteria

StoryAcceptance criteria
As purchasing, I want a daily reorder list so I can order before stock runs out.Products at or below reorder point appear with supplier and lead time, sorted by largest shortfall.
As a picker, I want stock to drop when I mark an order Picked so counts stay accurate.On Picked, on-hand falls by order quantity. If quantity exceeds on-hand, the pick is blocked and the shortfall is shown.
As finance, I want margin by category so I can see what drives profit.Cancelled orders excluded. Margin % = (price − cost) / price, rounded to 0.1.
As the operations manager, I want shipping time by region so I can find slow lanes.Only shipped or delivered orders count. Report shows order count and average days.

Reorder query

Joins products, inventory and suppliers, and orders by how far below reorder point each product is.

SELECT p.sku, p.name, i.on_hand, p.reorder_point, s.name AS supplier, s.lead_time_days
FROM products p
JOIN inventory i ON i.product_id = p.product_id
JOIN suppliers s ON s.supplier_id = p.supplier_id
WHERE i.on_hand <= p.reorder_point
ORDER BY (p.reorder_point - i.on_hand) DESC;

Margin by category

Excludes cancelled orders so the numbers reflect real revenue.

SELECT p.category, SUM(oi.qty * p.unit_price) AS revenue,
       ROUND(100.0 * SUM(oi.qty * (p.unit_price - p.unit_cost))
             / SUM(oi.qty * p.unit_price), 1) AS margin_pct
FROM order_items oi
JOIN orders o ON o.order_id = oi.order_id
JOIN products p ON p.product_id = oi.product_id
WHERE o.status <> 'Cancelled'
GROUP BY p.category ORDER BY revenue DESC;

Shipping time by region

SELECT c.region, COUNT(*) AS orders,
       ROUND(AVG(julianday(o.shipped_date) - julianday(o.order_date)), 1) AS avg_days_to_ship
FROM orders o JOIN customers c ON c.customer_id = o.customer_id
WHERE o.shipped_date IS NOT NULL
GROUP BY c.region ORDER BY avg_days_to_ship DESC;
