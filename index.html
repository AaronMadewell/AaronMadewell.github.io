How an order moves today
How it should move

        
Twelve stories, each with Given, When, Then acceptance criteria.
IDI want toAcceptance criteria
US-01Enter an order once with its line items.Given a customer and in-stock products, when I save an order, then the order and line items are stored and a product cannot repeat on one order.
US-02Reject zero or negative quantities.Given an order, when I add a line item with quantity 0 or less, then the system rejects it.
US-03Use only agreed order statuses.Given an order, when I set a status outside the five allowed, then the system rejects it.
US-04Keep product codes unique.Given an existing code, when I add a product with the same code, then the system rejects it.
US-05Point line items at real products and orders.Given a line item for a product that does not exist, when I save it, then the system rejects it.
US-06Block picks that exceed stock.Given 35 on hand, when I pick 500, then the pick is rejected, stock stays 35 and the shortfall is shown.
US-07Reduce stock when I pick.Given 60 on hand, when I pick 12, then on-hand becomes 48.
US-08See a daily reorder list.Given stock levels, when I open the list, then every product at or below reorder point shows with supplier and lead time, largest shortfall first.
US-09Have the list update as stock changes.Given a product above its reorder point, when a pick brings it to the point, then it appears on the next list.
US-10Report revenue and margin by category.Given orders in any status, when I run the report, then cancelled orders are excluded and margin is (price minus cost) over price, to one decimal.
US-11Report shipping time by region.Given orders with ship dates, when I run the report, then only shipped or delivered orders count, with order count and average days.
US-12Require a ship date on shipped orders.Given an order marked Shipped or Delivered, when I save it with no ship date, then the system rejects it.

        
TableColumns and rules
supplierssupplier_id (key), name, lead_time_days
productsproduct_id (key), sku (unique), name, category, unit_cost, unit_price, reorder_point, supplier_id
inventoryproduct_id (key), on_hand (never below 0)
customerscustomer_id (key), name, region
ordersorder_id (key), customer_id, order_date, status (5 allowed), shipped_date (required when Shipped or Delivered)
order_itemsorder_id + product_id (key), qty (above 0)

Defect log

          
IDWhat was wrongFix

            
D-001, mediumAn order could be saved as Shipped with no ship date, which would drop it from the shipping report.A check now requires a ship date on Shipped and Delivered orders and forbids one on the rest.

            
D-002, highA line item for a product that does not exist was accepted, because SQLite ignores foreign keys unless a setting is turned on.The schema turns the setting on, and the requirement is recorded for every connection.
